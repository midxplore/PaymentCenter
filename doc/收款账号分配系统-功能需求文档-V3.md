# 收款账号分配系统 — 功能需求文档

版本：V3.0
状态：待开发排期

---

## 一、背景与目标

平台需要维护一批收款账号/收款二维码资源池，每个账号/码对应一个总额度。业务方通过API按"收款类型 + 收款金额"获取一个额度充足的账号/码用于收款，系统同步生成订单跟踪本次收款；到账情况由外部系统异步上报（支持分次到账），最终形成一条完整、可审计的收款流水闭环。

**核心目标：**
1. 保证收款请求总能拿到一个额度够用的账号/码
2. 保证额度不超发、到账数据不丢失、全程可追溯
3. 只对经过授权的调用方开放，防止接口被滥用

---

## 二、角色定义

| 角色 | 说明 |
|---|---|
| 资源管理员 | 后台上传/维护收款账号或收款码及其总额度 |
| 业务调用方 | 调用API获取可用账号/码，用于收款场景 |
| 通知方 | 调用异步到账通知接口，上报某笔订单的实际到账情况 |
| 审计/运营人员 | 查看流水、处理异常到账台账 |

## 三、功能清单

### F1. 账号/收款码管理

| 编号 | 功能点 | 说明 |
|---|---|---|
| F1.1 | 新增账号/码 | 录入：类型标签、账号信息或二维码内容、总额度、备注 |
| F1.2 | 编辑与追加额度 | 支持修改备注、状态；支持对已有账号追加总额度（与新增上传共用同一维护入口，不单独做"充值"功能） |
| F1.3 | 启用/停用 | 停用后立即不参与匹配，历史订单不受影响 |
| F1.4 | 额度耗尽自动下架 | 剩余可用额度为0时自动标记为"已用完"，不再参与匹配；若后续需要继续使用，通过F1.2追加额度即可恢复参与匹配 |
| F1.5 | 列表查询 | 按类型、状态筛选，展示总额度/已用额度/剩余可用额度 |

### F2. 查询匹配接口（核心API）

调用方传入收款类型和金额，系统匹配一个账号/码并生成订单。

| 编号 | 功能点 | 说明 |
|---|---|---|
| F2.1 | 筛选条件 | 类型一致 + 状态启用 + 剩余可用额度 ≥ 请求金额 |
| F2.2 | 匹配规则 | 在满足条件的账号中，优先选择**剩余可用额度与请求金额最接近的一个**（最佳适配，优先消耗零散额度，避免大额度账号被小额订单占用）；若剩余额度相同，按上传时间最早的优先，保证规则确定、可复现 |
| F2.3 | 生成订单 | 匹配成功后创建订单（订单号、请求金额、匹配账号、状态=待到账、过期时间），过期时长使用全局统一配置 |
| F2.4 | 额度预占 | 匹配成功即锁定对应金额，防止被其他请求重复匹配导致超发 |
| F2.5 | 无匹配处理 | 无符合条件的账号时，返回明确的"无可用账号"错误，不生成订单 |
| F2.6 | 幂等支持 | 支持调用方传入外部业务单号，避免网络重试导致重复生成订单 |

### F3. 订单过期机制

| 编号 | 功能点 | 说明 |
|---|---|---|
| F3.1 | 全局过期时长配置 | 后台配置一个全局统一的订单等待到账时长，所有订单生成时按此配置计算过期时间 |
| F3.2 | 自动过期 | 超过过期时长仍未收到"完成"状态的到账通知，订单自动置为"已过期"，释放未达成部分的预占额度 |
| F3.3 | 过期后到账 | 过期后仍收到到账通知的，不计入原订单，进入异常到账台账（见F5） |

### F4. 异步到账通知接口（核心API）

| 编号 | 功能点 | 说明 |
|---|---|---|
| F4.1 | 接收到账通知 | 通知方传入订单号、到账金额、到账时间（及凭证号用于去重） |
| F4.2 | 支持分次到账 | 同一订单可多次上报，系统累加到账金额；累计金额达到请求金额时，订单自动置为"已完成"，额度正式扣减（从锁定转为已用） |
| F4.3 | 未达标 | 累计到账金额小于请求金额时，订单状态为"部分到账"，继续等待或至过期 |
| F4.4 | 超额到账 | 实际业务中超额到账概率极低；若发生，记录实际到账总额并在订单上备注差额信息，不做额外流程处理 |
| F4.5 | 通知去重 | 相同凭证号的到账通知重复上报时不重复累加金额 |
| F4.6 | 结果反馈 | 接口返回处理结果及当前订单状态（部分到账/已完成等） |

### F5. 异常到账台账

| 编号 | 功能点 | 说明 |
|---|---|---|
| F5.1 | 自动记录 | 找不到匹配订单（如已过期、订单号错误）的到账通知，自动进入异常到账台账，不丢弃 |
| F5.2 | 人工补录关联 | 支持运营人员将异常到账记录**手动关联**到某个具体订单，关联后触发该订单的到账累计逻辑（等同于F4.2的补充到账处理） |
| F5.3 | 处理状态跟踪 | 记录处理状态（待处理/已关联/确认无需处理）、处理人、处理时间 |

### F6. 安全接入控制

| 编号 | 功能点 | 说明 |
|---|---|---|
| F6.1 | 接口鉴权 | 每个接入方分配独立 API Key + Secret，请求需签名（如HMAC-SHA256） |
| F6.2 | 权限隔离 | "查询匹配接口"与"到账通知接口"权限分开授权，避免调用方越权调用通知接口伪造到账 |
| F6.3 | 通信加密 | 全链路HTTPS |
| F6.4 | 敏感信息脱敏 | 账号/收款码等敏感信息在接口返回及后台展示时按权限脱敏 |
| F6.5 | 异常访问告警 | 鉴权失败、异常高频请求记录日志并告警 |

### F7. 审计与流水闭环

| 编号 | 功能点 | 说明 |
|---|---|---|
| F7.1 | 订单全生命周期记录 | 创建时间、匹配账号、过期时间、每一次到账通知明细、最终状态及时间，完整留存 |
| F7.2 | 账号维度审计 | 按账号查询：总额度、已用/剩余额度、关联的所有订单及到账明细 |
| F7.3 | 操作日志 | 后台所有增删改操作（新增账号、追加额度、停用、异常台账人工关联）记录操作人、时间、内容，不可删改 |
| F7.4 | 流水不可篡改 | 订单及到账记录只增不改，状态变更通过追加记录实现 |
| F7.5 | 数据导出 | 支持按时间区间导出订单及流水数据，供外部对账使用 |

## 四、核心流程

```
资源管理员上传/维护账号+总额度（额度耗尽可追加）
        ↓
业务调用方发起【查询匹配接口】(类型, 金额, [外部单号])
        ↓
筛选：类型匹配 + 启用 + 剩余可用额度 ≥ 金额
        ↓
   有匹配？── 否 → 返回"无可用账号"
      │ 是
      ↓
按"剩余额度最接近请求金额"选取 → 锁定额度 → 创建订单(全局过期时长) → 返回账号/码+订单号
        ↓
【等待到账】
        │
        ├─ 通知方调用【到账通知接口】(订单号, 金额, 时间) ── 可多次
        │        ↓
        │   累计金额 ≥ 请求金额 → 订单完成，额度正式扣减
        │   累计金额 <  请求金额 → 部分到账，继续等待
        │
        └─ 超过全局过期时长仍未完成 → 订单过期，释放未达成部分预占额度
                   ↓（过期后/找不到订单的到账通知）
              进入异常到账台账 → 人工补录关联到对应订单（如有）
```

## 五、关键数据字段设计

**账号/收款码表**
- 类型、账号信息或二维码内容、总额度、已用额度（累计确认到账）、锁定中额度（待完成订单占用）、状态、创建/更新时间

剩余可用额度 = 总额度 − 已用额度 − 锁定中额度

**订单表**
- 订单号、外部单号（幂等用）、请求金额、匹配账号ID、累计到账金额、状态（待到账/部分到账/已完成/已过期）、创建时间、过期时间、完成时间

**到账通知记录表**（一个订单可对应多条）
- 订单号、本次到账金额、到账时间、凭证号（去重）、通知方标识、原始请求报文、接收时间

**异常到账台账**
- 到账信息（金额、时间、凭证号等）、原因（无匹配订单/已过期）、关联订单号（人工补录后填入）、处理状态、处理人、处理时间

**操作审计日志**
- 操作人、操作类型、操作对象、操作前后值、时间、来源IP

## 六、接口清单

| 接口 | 调用方 | 核心入参 | 核心出参 |
|---|---|---|---|
| 查询匹配接口 | 业务调用方 | 收款类型、金额、外部单号（可选） | 订单号、账号/码信息、过期时间 |
| 到账通知接口 | 通知方 | 订单号、到账金额、到账时间、凭证号 | 处理结果、当前订单状态、累计到账金额 |
| 订单状态查询接口 | 业务调用方 | 订单号 | 当前状态、累计到账金额、过期时间 |

## 七、验收标准

| 场景 | 预期结果 |
|---|---|
| 请求金额超过所有账号剩余额度 | 返回"无可用账号"，不生成订单 |
| 多个账号同时满足条件 | 系统选择剩余额度与请求金额最接近的账号 |
| 两个请求同时匹配同一账号且合计超额度 | 只有一个成功锁定，另一个匹配下一个可用账号或返回无可用，不能超发 |
| 到账通知分3次到达，累计达到请求金额 | 前两次记为"部分到账"，累计达标后订单变为"已完成" |
| 订单过期后才收到到账通知 | 不计入原订单，进入异常到账台账 |
| 运营人员将异常到账人工关联到某订单 | 该订单按此次金额累加到账，正常走完成判断逻辑 |
| 重复上报同一笔到账通知 | 不重复累加金额 |
| 未授权调用方尝试调用到账通知接口 | 鉴权失败，拒绝请求并记录日志 |
| 账号额度耗尽后追加新额度 | 追加后立即恢复参与匹配 |
| 查询某账号使用情况 | 能准确看到总额度、已用、剩余，及关联的每笔订单/到账明细 |

## 八、本期明确不做（避免过度设计）

- 不做周期性额度（日/周/月限额），仅维护一个总额度
- 不做退款相关功能
- 不做多因子智能路由（成功率、渠道优先级等），仅按"额度最接近"匹配
- 不做IP白名单等增强安全措施（如后续有需要可在API Key鉴权基础上迭代）
- 不做超额到账的自动化处理流程，仅做备注记录
