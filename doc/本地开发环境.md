# 本地开发环境

> 目标：在开发机上把「收款账号分配系统」跑起来并稳定调试。
> 本文只讲**怎么跑**与**为什么这么跑**；业务/接口契约见 `收款账号分配系统-技术设计方案.md`。

---

## 一、一条命令

```bash
scripts/dev-up.sh          # 起库 → 构建 → 后端 → schema 纠偏 → 守卫校验
```

跑完会打印后端地址、Swagger、日志路径与前端启动命令。前端另开一个终端：

```bash
cd Web && env -u NODE_OPTIONS npm run dev     # http://localhost:8888
```

停止：`scripts/dev-down.sh`（加 `--with-db` 连库一起停）。

全部 HTTP 端到端回归，一条命令：

```bash
scripts/regress-all.sh --with-login   # 自动关验证码 → 串行跑 4 个脚本 → 自动还原并自验
```

（不加 `--with-login` 时它只做**前置检查**：后端在跑、验证码已关，不满足就拒绝并退出 2 ——
不会「什么都没跑却报通过」。为什么必须串行、为什么验证码要先关，脚本头注释写了原因。）

## 二、工具链与路径坑

本机有四个「装了但不在 PATH 上 / 名字对不上」的东西，**这是本地起不来的头号原因**：

| 工具 | 正确用法 | 说明 |
|---|---|---|
| dotnet | `/usr/local/share/dotnet/dotnet` | **不在 PATH**，脚本里已写绝对路径 |
| docker | `export PATH="/usr/local/bin:$PATH"` | OrbStack 装了但不在 PATH |
| node / npm | `env -u NODE_OPTIONS npm …` | `NODE_OPTIONS` 会干扰 Vite |
| python | `~/.workbuddy-ai/binaries/python/envs/default/bin/python` | **只有这个 venv 里有 psycopg2**，回归脚本与守卫都靠它 |

★ **第五个坑：时区必须固定 +08:00。**

```bash
export TZ=Asia/Shanghai        # 容器编排 / systemd / 宿主都要设
```

这不是「建议」而是**硬前提**：`pay_*` 的全部时间列都是 `timestamp without time zone`，
写入用 `DateTime.Now`（本地墙上时间）。进程时区一旦不是 +08（容器默认常是 UTC），
历史行是 +08、新行是 UTC，**同一列混入两种含义且不会报任何错** ——
对账、订单超时判断、订单号日期前缀会全部静默错位。

所以 `PayCenterStartup` 在启动期就校验，不符合**直接抛异常拒绝启动**：

```
✗ 时间基准不符合约定：本进程所在时区不是固定 UTC+08:00。
  → 修复：设置环境变量 TZ=Asia/Shanghai 后重启（容器编排与 systemd 都要设）。
```

看到这段就是时区问题，不用去查数据库。契约与理由见设计方案 §14。

端口分配：

| 用途 | 端口 | 备注 |
|---|---|---|
| 后端 | **5005** | 不要用 5000 —— macOS 的 AirPlay 占着它 |
| 前端 | **8888** | `Web/.env` 的 `VITE_PORT` |
| PostgreSQL | **55432** | 不是 5432，避免与本机其他 PG 冲突 |

## 三、数据库是怎么定的（改之前必须看懂）

```
appsettings.json   ConfigurationScanDirectories = ["Configuration", "", "ConfigurationLocal"]
        │
        │  Furion 按顺序扫描，★ 后扫描的优先级最高（高于环境变量与根 appsettings*.json）
        ▼
bin/<cfg>/ConfigurationLocal/LocalOverride.json      ← 覆盖 ConnectionConfigs[0] 的 DbType / 连接串
        │
        │  没有这个文件时
        ▼
Configuration/Database.Development.json              ← 回落目标：SQLite
```

**三个必须知道的事实：**

1. ★ **Furion 读的是输出目录（`bin/`）里的那份，不是仓库里的源文件。**
   改了 `ConfigurationLocal/LocalOverride.json` 而不重新 build，运行时用的还是旧副本 ——
   表现为「我明明改了连接串，怎么没生效」。
   反过来说：**只想临时换库，改 bin 里那份就够，不必碰源文件**（`scripts/run-backend-pg.sh` 的 `DB=sqlite` 就是这么做的）。

2. ★ **`ConfigurationLocal` 目录必须存在。**
   Furion 对扫描列表里的**每一个**目录无条件调 `Directory.GetFiles`，目录不存在直接抛
   `DirectoryNotFoundException`。这个异常发生在**主机构建阶段**，早于日志系统初始化 ——
   现象是「进程直接退出，`logs/` 里什么都没有，只有控制台一段栈」，极难归因。
   目录由 `Admin.NET.Web.Entry.csproj` 的 `EnsureConfigurationLocalInOutput` /
   `EnsureConfigurationLocalInPublish` 两个 `MakeDir` 目标保证（MSBuild **不复制空目录**，
   光靠 `<Content Update="ConfigurationLocal\**\*.json">` 在有 json 时才产出目录）。

3. ★ **连接串只有一个来源。**
   `Configuration/Database*.json` 含连接串，属受保护配置（**不要读、不要改**，读取会被沙箱拦截）。
   本地切库一律走 `ConfigurationLocal/LocalOverride.json`。
   `.NET 配置对数组按索引合并`，所以只覆盖 `DbType` 与 `ConnectionString` 两个字段，
   其余（`ConfigId` / `DbSettings` / `TableSettings` / `SeedSettings`）自动继承。
   **文件名必须唯一**：Furion 按文件名去重，叫 `Database.json` 会被静默跳过。

## 四、三个已修的坑（都曾是「静默」或「必崩」级）

### 4.1 发布产物启动即崩 —— 已修

`ConfigurationLocal` 不在 `ConfigurationScanDirectories` 里能删，但 `CopyToPublishDirectory=Never`
导致它**不进发布产物**，而 MSBuild 又不复制空目录 → `dotnet publish` 出来的包
在 `AddJsonFiles` 阶段抛 `DirectoryNotFoundException`，**生产包起不来**。
现已用 `MakeDir` 目标在发布目录里补建该目录（实测：修复前崩、修复后正常启动）。

### 4.2 扫描列表双来源 → 静默回落到 SQLite —— 已修

`appsettings.Development.json` 原先写 `["Configuration", ""]`，比 `appsettings.json` **少一项**。
它「看起来能跑」只是因为 .NET 对**数组按下标合并**：下标 0/1 被覆盖，下标 2（`ConfigurationLocal`）
作为更早 provider 留下的键**侥幸存活**。

于是任何人把两份配置「顺手对齐」成一致的两项，`ConfigurationLocal` 就静默掉出扫描列表 →
应用**静默回落到 SQLite**，全程不报错，只在启动日志里留一行 `初始化数据库 Sqlite`。

现已**删掉** `appsettings.Development.json` 里的 `ConfigurationScanDirectories`，
扫描列表**只由 `appsettings.json` 一处定义**。
`dev-up.sh` 还会在启动后 grep 这行日志并**直接告警**，不再依赖人去看。

### 4.3 「移走 json 就能切回 SQLite」是错的 —— 已修

原 `run-backend-pg.sh` 注释这么写，但两个方向都不成立：

- **不重新 build**：Furion 读的是 `bin/` 副本，源文件移走**不影响**运行时 → 还是连 PG（你以为切了，其实没切）。
- **重新 build**：`bin/` 里的目录随之消失 → **下次启动直接崩**（不是回落到 SQLite）。

正确做法（`scripts/run-backend-pg.sh` 的 `DB=sqlite` 已实现）：
**只临时改名 `bin/` 里那一份**，源文件与目录都不动，进程退出时自动还原。

> ⚠️ SQLite 只是应急回落。**正式开发请用 PG** —— 额度预占依赖 `FOR UPDATE` 行锁，
> SQLite 没有这个语义，并发行为不可比，压测结论也不可迁移。

## 五、常见故障速查

| 现象 | 原因 | 处理 |
|---|---|---|
| 进程秒退，`logs/` 里什么都没有，控制台有 `DirectoryNotFoundException: .../ConfigurationLocal` | 扫描目录不存在（被删 / 空目录没建出来） | 重新 build（`MakeDir` 会补建）；别删 `ConfigurationLocal` 目录 |
| 后端起来了，但数据「不对」/ 表结构是旧的 | **静默回落到了 SQLite** | 看启动日志有没有 `初始化数据库 Sqlite`；确认 `bin/<cfg>/ConfigurationLocal/LocalOverride.json` 存在 |
| 改了连接串没生效 | Furion 读 `bin/` 副本 | 重新 build，或直接改 `bin/` 里那份 |
| 改了业务代码，行为没变 | `dotnet run --no-build` 跑的是旧二进制；而 `dotnet test` **只刷新 `Application/bin`，不刷新 `Web.Entry/bin`** | 先 `dotnet build Admin.NET.sln` |
| 登录报「验证码错误」/ 脚本报 `'NoneType' object has no attribute 'get'` | 租户图形验证码默认开启 | 见下节 |
| 接口 401 / 403，或**任何已登录用户都能调** | 权限是**黑名单模型**，见下节 | 补按钮菜单种子 |
| 页面白屏 | 菜单 `component` 在 `import.meta.glob` 里**命中数 > 1**（如同时有 `index.vue` 与 `index2.vue`） | 保证唯一命中 |
| 测试报「没有可用测试」/ DI 里没有任何应用服务 | 混入了两套 Furion（`Furion` vs `Furion.Pure`） | 测试工程必须用 `Furion.Pure.Xunit` |

## 六、调接口前必须知道的三件事

1. **图形验证码默认开启。**
   注意 `SysTenantSeedData.cs` 有**两份**，生效的是
   `Admin.NET.Application/SeedData/SysTenantSeedData.cs`（`[SeedData(500)]`，Id 与框架一致 = 重写框架种子）；
   `Admin.NET.Core/SeedData/SysTenantSeedData.cs` 那份带 `[IgnoreUpdateSeed]`，改它没用。
   而且**租户列表有缓存 → 直接改库也无效**，必须改种子再重启。
   浏览器调试正常输入即可；用 Postman / 脚本调接口要先关掉。

2. **登录口令必须 SM2 加密。**
   框架自带的 `/api/sysCommon/sM2Encrypt/{plainText}` **自身要登录**，死循环。
   用 Node 的 `sm-crypto-v2`，参考实现见 `scripts/_pay_common.py` 的 `sm2_encrypt`
   （`sm2.doEncrypt(pwd, publicKey, 1)`，`1` = C1C3C2）。

3. **权限是黑名单模型。**
   `JwtHandler` 按 `path.EndsWith(permission)` 匹配，且
   `apiList[1] = allButtonList.Except(userButtons)` ——
   **没有对应按钮权限的接口 = 任何已登录用户都能调**。
   两个连带坑：
   - `permission` 要写接口路由的**尾部**（如 `payAccount/page`），**不要**写全路径；
   - 路由由**方法名推导**，不一定等于方法名（`CreateSecret()` → `/api/sysOpenAccess/secret`），
     权威来源是 `Web/src/api-services/**` 的 `localVarPath`。
   - **超管免菜单授权**，所以新菜单只加自己的种子；非超管要在「角色管理」里勾。

## 七、改了代码之后跑什么

```bash
# 1. 构建（0 warning / 0 error 是基线）
/usr/local/share/dotnet/dotnet build Admin.NET/Admin.NET.sln

# 2. 单元测试（走真实 PG，需先 dev-up）
/usr/local/share/dotnet/dotnet test Admin.NET/Admin.NET.Test/Admin.NET.Test.csproj

# 3. schema 漂移守卫 —— ★ 改了实体 / 入参 DTO 必跑
~/.workbuddy-ai/binaries/python/envs/default/bin/python scripts/pay_schema_guard.py

# 4. HTTP 回归（需后端在跑）
~/.workbuddy-ai/binaries/python/envs/default/bin/python scripts/pay_allocate_stress.py
~/.workbuddy-ai/binaries/python/envs/default/bin/python scripts/pay_notify_regression.py
~/.workbuddy-ai/binaries/python/envs/default/bin/python scripts/s6_admin_probe.py
~/.workbuddy-ai/binaries/python/envs/default/bin/python scripts/pay_openaccess_gate_probe.py
```

前端（`vite build` 只校验 import 路径、不校验对象成员，所以**类型检查是单独一条**）：

```bash
cd Web

# 5. 类型检查闸门 —— ★ 改了 src/views/paycenter/ 下任何文件必跑
env -u NODE_OPTIONS npm run typecheck       # 只圈本模块，必须 0 错；退出码非 0 = 有错
env -u NODE_OPTIONS npm run typecheck:all   # 看全量明细（含已登记的框架/生成物债务）

# 6. 构建
env -u NODE_OPTIONS npm run build
```

`npm run typecheck` 的输出分三块，看最后一行就够了：

| 桶 | 含义 | 是否阻断 |
|---|---|---|
| **本模块**（`src/views/paycenter/`） | 我们自己的代码 | ★ **必须 0 条**，否则退出 1 |
| **既有债务** | Swagger 生成物 + 框架自带代码，逐条写了「为什么不在这里修」 | 不阻断，但**计数始终打印**（含 0 条），防止悄悄增长 |
| **未归类** | `src/` 下没人认领的新路径 | ★ **也让闸门失败** —— 否则它的错误会从统计中消失 |

> 接入时全量是 **458 条**，其中本模块只有 **7 条**。所以闸门**不追求把噪声清零**（那是框架和代码生成器的事），
> 而是保证「我们写的代码」这一块始终干净。**改完前端先跑它，再跑 build。**

改完自检三项（类型检查覆盖不到的**运行期契约**）：① 菜单 `component` 唯一命中
② `v-auth` 串都能在菜单 permission 里找到 ③ 调用的 API 方法名在 `api-services` 里真实存在。

> 可选：只改了一两个 `.vue` 时，可以先跑单文件语法校验（秒级，不做类型检查）：
> `cd Web && env -u NODE_OPTIONS node script/check-sfc.cjs src/views/paycenter/xxx/index.vue`
> 它只覆盖模板编译这一层；类型问题仍要 `npm run typecheck`。

## 八、测试造数与清理

回归脚本走**直连 PG 造数 / 核对**；**并发只走真实 HTTP**
（SqlSugarScope 的连接按请求上下文隔离，进程内并发测不出真并发）。

★ **清理必须包含 `pay_audit_log`**，否则「清干净了」是假的（实测漏 20 行而脚本照打印「已清干净」）。
只能按 **`clientkey`（= accessKey，测试前缀挂这里）** 或**显式 `targetid`** 清，
**不能按 `targetno`** —— 订单号是纯数字自包含雪花，`LIKE '<前缀>%'` 永远匹配不到。
两个连带点：导出审计 `action=7` 不带任何测试标识，只能按**运行时间窗**清；
**账号删除本身也写 `action=5`**，所以账号审计要**删除前后各清一次**。

## 九、前端

- **后端驱动路由**：菜单种子 → `/api/sysMenu/loginMenuTree` → `dynamicImport`（`startsWith` 匹配），
  **命中数必须恰好 1**（0 → 空白页；**>1 → 返回 `false` → 白屏**）。
- 约定：一级 `type=1` + `component=Layout`；二级 `type=2` + `component=/paycenter/xxx/index`；
  三级按钮 `type=3` 只填 `permission`。
- ★ **菜单种子随模块走**（`PayCenter/SeedData/PayMenuSeedData.cs`），**不放**框架的
  `SysMenuSeedData.cs`（模块拆出去时菜单一起走）。例外：`sysOpenAccess/*` 的按钮属框架页面，放 Core。
- ★ `[IgnoreUpdateSeed]` **只跳过「更新已有行」，新增行照样插入** → 往已有种子类里加行**会生效**。
- ★ **类型检查的边界**：`npm run typecheck` 能查出「调错方法名 / 用错字段名 / 可空字段没判空」，
  但**查不出**下面这些（都是运行期才暴露的契约）：
  - 菜单 `component` 是否唯一命中（路由是后端下发的字符串）；
  - `v-auth` 串是否真的在菜单 permission 里；
  - 后端 `[MaxLength]` / `[Required]` 之类的**服务端**校验。

  → 所以类型检查通过**不等于**页面能打开，自检三项（见 §七）仍要做。

- ★ **`el-date-picker` 一律带 `value-format="YYYY-MM-DD HH:mm:ss"`**（本地格式字符串），
  而 Swagger 生成的模型把 `DateTime` 映射成 `Date` —— 两者**故意不一致**。
  传真正的 `Date` 会让 axios 序列化成带 `Z` 的 UTC ISO，后端按 UTC 解析 → 时间区间**整体偏 8 小时**。
  **不要**为了让类型报错消失就改成 `new Date(...)`；构造逻辑统一收在
  `src/views/paycenter/utils/exportParams.ts`（文件头写了原因）。
  > 时间基准**已定案**（#20 关闭）：统一为本地 +08，不改 UTC + `timestamptz`，
  > 理由与「若将来要迁的成组变更清单」见设计方案 §14.4。本节做法与该结论一致，无需改动。
